Project overview

A working research prototype that collects real gold, silver and platinum observations, preserves their origin and frequency, and publishes a traceable analytical dashboard.

Open recorded-data dashboard ↗

Problem & objectives

Spot quotes, monthly averages and reference exchange rates measure different things. The system keeps them separate so analysis does not silently mix instruments, units or time frequencies.

My responsibilities

Designed and implemented provider adapters, validation rules, SQL storage, read-only API, dashboard and model evaluation. This repository implementation is a research project, with no claimed client engagement or trading results.

Requirements & acceptance criteria

  • Retain provider timestamps and response SHA-256 provenance.
  • Reject invalid prices, units, dates and duplicate batch keys before loading.
  • Make ingestion idempotent; preserve validated data during source outages and report failure explicitly.
  • Separate monthly prices, spot quotes and daily reference FX.
  • Evaluate models chronologically against a naive baseline before publishing a forecast.

System workflow

  1. Fetch World Bank workbook, Gold API quotes and Frankfurter FX
  2. Validate source, unit, timestamp and finite positive value
  3. Transactional UPSERT into SQLite
  4. Evaluate monthly model using expanding-window validation
  5. Publish JSON, CSV and SHA-256 manifest

Database & architecture

SQLite persistence is verified. observations uses a composite key of source, series, frequency and observed_at. pipeline_runs, source_runs and model_runs preserve operational history. PostgreSQL support and an Airflow DAG are supplied but their runtime has not been tested.

The Python server exposes read-only health and snapshot endpoints. GitHub Pages serves the recorded JSON export; it does not run the Python service.

Implementation & data sources

The recorded export contains 2,403 World Bank monthly observations (801 each for gold, silver and platinum), two timestamped spot quotes and one USD/THB reference rate. Export time: 3 November 2026, 17:14:09 UTC. These are recorded observations, not current streaming prices.

Testing & validation

Twelve unit tests passed for validation, atomicity, idempotence, outage handling, export consistency and chronological model evaluation. The actual Python HTTP server passed eight route checks. Browser Preview checks at 360, 390, 768 and 1440 CSS pixels found no horizontal overflow; physical devices were not tested.

Implementation acceptance evidence ↗

ML evaluation

HistGradientBoosting uses lagged monthly gold, silver and platinum features. An expanding-window evaluation produced 36 holdout predictions for October 2023–September 2026. MAE: candidate 133.60 versus naive 129.53 USD/troy oz. The candidate did not outperform the baseline; it is not promoted and no point forecast is published.

This is retrospective evaluation on current-vintage monthly data. Publication latency is not reconstructed; it is not a point-in-time trading backtest.

Results & deliverables

Executable ingestion pipeline, SQLite schema, read-only API, real-data dashboard, downloadable observations, provenance manifest, automated checks and reproducible monthly ML evaluation.

Real system evidence

Limitations & lessons learned

PostgreSQL, Docker and Airflow runtime remain untested. The public dashboard is a recorded export. The evaluated model loses to a simple baseline, demonstrating why honest baseline comparison and forecast gating are necessary before operational use.
