Project overview

A working research prototype that collects real gold, silver and platinum observations, preserves their origin and frequency, and publishes a traceable analytical dashboard.

Open recorded-data dashboard ↗

Problem & objectives

Spot quotes, monthly averages and reference exchange rates measure different things. The system keeps them separate so analysis does not silently mix instruments, units or time frequencies.

My responsibilities

Designed and implemented provider adapters, validation rules, SQL storage, read-only API, dashboard and model evaluation. This research project focuses on traceable data and reproducible evaluation.

Requirements & acceptance criteria

  • Retain provider timestamps and response SHA-256 provenance.
  • Reject invalid prices, units, dates and duplicate batch keys before loading.
  • Make ingestion idempotent; preserve validated data during source outages and report failure explicitly.
  • Separate monthly prices, spot quotes and daily reference FX.
  • Evaluate models chronologically against a naive baseline before publishing a forecast.

System workflow

  1. Fetch World Bank workbook, Gold API quotes and Frankfurter FX
  2. Validate source, unit, timestamp and finite positive value
  3. Transactional UPSERT into SQLite
  4. Evaluate monthly model using expanding-window validation
  5. Publish JSON, CSV and SHA-256 manifest

Database & architecture

SQLite persistence is verified. observations uses a composite key of source, series, frequency and observed_at. pipeline_runs, source_runs and model_runs preserve operational history. Docker and PostgreSQL 16.15 are verified on GitHub Actions, including replay idempotence and persistence after an actual container restart. Airflow 2.10.5 ran all three DAG tasks successfully through its DAG CLI. Airflow metadata uses isolated SQLite; business observations use PostgreSQL.

The Python server exposes read-only health and snapshot endpoints. GitHub Pages serves the recorded JSON export; it does not run the Python service.

Implementation & data sources

The recorded export contains 2,406 World Bank monthly observations (802 each for gold, silver and platinum), four recorded spot quotes and two USD/THB reference rates. Export time: 4 November 2026, 06:56:26 UTC. These are recorded observations, not current streaming prices.

ML evaluation

HistGradientBoosting uses lagged monthly gold, silver and platinum features. An expanding-window evaluation produced 36 holdout predictions for November 2023–October 2026. MAE: candidate 138.14 versus naive 135.47 USD/troy oz. The candidate did not outperform the baseline; it is not promoted and no point forecast is published.

This is retrospective evaluation on current-vintage monthly data. Publication latency is not reconstructed; it is not a point-in-time trading backtest.

Model card & methodology ↗

Additional research compared 16 configurations, including the naive baseline, drift, Ridge, Gradient Boosting and Random Forest, selected on pre-holdout validation. The naive baseline remained best. The research gate requires at least 5% lower MAE and RMSE and winning at least two of three annual folds. No candidate passed. The previously inspected holdout is disclosed as reused historical evidence.

Limitations & lessons learned

Docker, PostgreSQL and Airflow are verified in an isolated GitHub Actions runtime. Daily refresh is configured for 13:17 Asia/Bangkok and its first complete run passed through export commit and GitHub Pages rebuild. Services are ephemeral, with recorded observations persisted in Git; no continuously hosted database, Airflow UI or scheduler is claimed. The public dashboard is a recorded export. The evaluated model loses to a simple baseline, demonstrating why honest baseline comparison and forecast gating are necessary before operational use.
