Project overview

เชื่อมความต้องการของเจ้าของบริษัทกับเว็บไซต์แสดงสินค้า บริการ และระบบจัดการเนื้อหาสำหรับทีมงาน

My responsibilities

ประสานงานกับเจ้าของบริษัท รวบรวมความต้องการ ออกแบบ Flow และพัฒนาเว็บไซต์พร้อมระบบจัดการเนื้อหา

Business problem & objectives

บริษัทต้องการพื้นที่นำเสนอสินค้า บริการ และผลงาน พร้อมให้ทีมงานปรับเนื้อหาได้โดยไม่ต้องแก้ Source Code ทุกครั้ง เป้าหมายคือเชื่อมเว็บไซต์สาธารณะกับ CMS และกำหนดสิทธิ์การจัดการให้ชัดเจน

ขอบเขตเป็นเว็บไซต์แค็ตตาล็อกและ CMS ไม่มีตะกร้า Checkout หรือรับชำระเงินอัตโนมัติ

Requirement analysis

เริ่มจากการพูดคุยกับเจ้าของบริษัทเพื่อทำความเข้าใจเนื้อหาและกระบวนการจัดการเว็บไซต์ เอกสารที่เผยแพร่ต่อไปนี้จัดทำจาก Source Code ภายหลัง แยกข้อกำหนดที่พบในระบบออกจากข้อเสนอที่ยังต้องยืนยัน

System architecture & database design

Node.js / Express แสดงหน้าเว็บด้วย EJS แยก Route ของ Public Website และ Admin CMS ข้อมูลเนื้อหาเก็บเป็น JSON ใน db.json ส่วนรูปภาพเก็บใน Upload Directory ระบบนี้ไม่ได้ใช้ SQL Database

มี Docker Compose และแนวทางกำหนด DATA_DIR / UPLOAD_DIR เพื่อแยกข้อมูลที่ต้องคงอยู่จากตัวแอปพลิเคชัน

Testing & validation

4 November 2026: authenticated read-only inspection opened all 12 primary admin menu pages, product brands and an existing product editor. DAIKIN filtering returned 5 visible rows; searching FTKF returned 1; a no-match search returned 0.

Thirteen public HTTP GET checks returned 200 and fourteen anonymous admin GET checks redirected to login. Two security-header unit tests passed for header logic. These observations do not establish CRUD, upload, editor-role enforcement, restart persistence or owner UAT acceptance.
